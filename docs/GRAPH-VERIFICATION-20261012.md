## 实际验证

验收使用合成资料，不给员工发送消息，不写生产数据库。PostgreSQL 使用独立
任务容器和严格校验名称 `knowseam_test` 的数据库；Neo4j 使用独立回环端口
19847、独立数据目录的 Community 5.26.32 实例。外部推理使用确定性替身；
不是用替身代替数据库。Neo4j 官方压缩包 SHA256：

`d279ae6a9b38034280681a558b0cd222dce89f87cc3d9867f1f7bd28ef5ebc30`

Linux 全量命令（需显式设置隔离测试 DSN 和 Neo4j URI）：

```bash
PYTHONPATH=src SUITEHARNESS_SOURCE_PATH=/srv/suite-harness/src \
  .build-public-release-20261010/test-env/bin/python -m pytest \
  --basetemp=/opt/tmp/ksg1012-final -q -rs -p no:cacheprovider
```

结果：**528 passed、15 skipped、17 subtests passed**，耗时 41.95 秒。
两条第三方 WebSocket 弃用警告。原始输出保存在
`.build-graph-20261012/full-tests.log`。

15 个跳过项是既有 Docling 真解析环境／容器／预加载模型或可选 Torch 依赖
未提供；没有跳过本次新增图谱集成测试。覆盖内容包括：

- 文档发布与事件入队同事务，故障注入证明发布回滚。
- 源撤销、活动版本替换、部门和指定员工权限、企业范围隔离。
- 逐块抽取中撤销后不再发送剩余块；已发送请求不能撤回。
- 无权限中间关系不进入下一跳；遍历及重排期间撤权，依赖路径结果被过滤。
- 独立向量/BM25 候选保留，图存储及最终图证据读取故障显式降级。
- 最终结果 `limit=1` 时图候选失效，仍能返回基础通道候选。
- 过期租约、旧 worker 不能提交新租约或抢不同指纹任务、最多三次失败尝试。
- 图写失败后复用已经提交的抽取检查点，旧事件不能覆盖新图版本或删除。
- 真实 Neo4j 并发旧／新版本替换、完整 service 的融合—重排—最终授权链路。
- 撤销后恢复且正文未改变的文档不会遗漏图谱任务。
- 首次启用或本体／模型指纹变化自动补建，查询参数变化不重新抽取。

## 当前运行状态与后续启用

已核实私有 `config.container.json` 的 `graph.enabled=false`。生产 A/B、知识库
API、同步工作进程和 PostgreSQL 没有重启或切换；原容器启动时间保持不变。
本次任务测试实例在验收后停止，生产数据没有迁移或删除。

这次完成的是代码与部署能力，不是生产图谱激活。启用时仍需：

1. 指定企业批准的抽取模型地址、模型名／版本和凭据，配置集合本体。
2. 准备私有 Neo4j 密码及专用数据卷，按 `GRAPH-STORAGE.md` 初始化并部署。
3. 查询 graph-status、确认文档投影完成，再对真实资料做业务准确率验收。

确定性测试不证明真实抽取准确率、模型费用或生产吞吐量。百万规模、跨企业
SaaS 管理、图数据库高可用、自动跨集合实体合并和全局图摘要不在本次实现中。
