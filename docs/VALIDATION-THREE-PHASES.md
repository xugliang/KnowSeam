## 3. 本轮发现并闭环的问题

1. 图通道最终校验只保护路径，独立向量/BM25 候选可能漏掉最新撤权。新增复现，
   将独立候选和路径证据统一交给当前 SQL 校验；图错误降级也再次验证。
2. 新客户端与旧 v1 解析服务的规范指纹不一致。按服务端声明版本校验，
   保留重启/输出指纹变化拒绝测试；两个旧测试替身也修正为返回其声明的版本。
3. 解析镜像缺少新增表格纯依赖。依照 Dockerfile 的真实 COPY 闭包执行导入，
   先复现缺失，再补齐 identifiers/tables 依赖。
4. 视觉能力仅根据配置报告就绪。现在检查活跃 runtime、模型指纹和预热状态；
   缺进程、错误指纹、未预热均不报告可用。
5. 视觉 Docker 构建白名单遗漏锁文件与离线 wheelhouse。新增失败测试后，只加入必要白名单，
   不将私有配置、权重或其他构建资料加入镜像上下文。
6. 数据库测试组合失败：先执行 reuse 的用例留下启用来源，后续 legacy 全库就绪检查正确拒绝。
   用例退出时仅禁用该随机测试公司自己的来源，保留记录排障；未修改生产校验。
   最小复现由 1 passed/9 errors 变为 10 passed，最终组合通过。

主会话实施；独立只读审查已完成，重要问题以复现测试闭环。审查不是全面安全或质量证明。
没有另开用户会话派发实现任务。没有将缺模型/规模/权限适配的事项降级成“轻微瑕疵”。

## 4. 性能与未达门槛项

合成脚本只访问隔离库，无模型调用和企业原文。1k/10k 可见块通过；
10k 可见块场景追加 100k 隐藏块后，可见 BM25 结果/分数保持不变。
此前该计划记录的 shared-postings P95 为 237.92 ms（无隐藏）及 428.47 ms（100k 隐藏）。
这不是生产 SLA，不能推广到任意授权集合、真实向量和全 Agent 耗时。

100k 可见＋100k 隐藏在 512 MiB 隔离容器（含 tmpfs）OOM，未通过。
没有修改共享服务器限额来绕过；后续需要批准独立压测预算，再记录执行计划、内存和资源曲线。
该失败不是生产 PostgreSQL 或产品 A/B 故障。

下列是与原计划/默认工作流存在差异或需要明确限制的决定，不是隐含承诺：

1. 沿用原服务器仓库；本地仅为已授权 apply_patch 镜像。遵守不另建开发仓要求；代价是共享脏目录整合更需保留基线和用户改动。
2. 保留 T00–T17 编号及手工持久账本，未强套技能脚本的 Task N 解析器；代价是状态必须逐项核验。
3. 不自动提交混有用户既有修改的工作树，也不推送或上线；代价是后续发布需单独审查提交范围。
4. 元数据过滤仅来自可信目录并作用于有界候选；代价是可能少召回，完整枚举使用目录，不能宣称全库覆盖。
5. 保留 100k OOM 失败，不擅增资源；代价是本轮规模验收未完成。
6. 图片必须重新鉴权，并收窄到 MCP 当前请求身份/集合；代价是不提供可直接转发的公开永久图片链接。
7. 不自动重写损坏的不可变共享缓存，先安全拒绝；代价是需要明确修复操作，不满足原计划“仅导致自动重算”的恢复目标。
8. 对未抽取旧版本如实报告 partial，不用当前事实冒充历史；代价是快速更新情况下事实历史不全。同一已关闭事实身份禁止复活；代价是重复纠错重开尚不支持。
9. 不能完整核实飞书私有继承授权时拒绝；代价是该类资料暂不可用，而不是扩大权限。
10. 新解析客户端先升级、再升级服务端；旧客户端不保证接受新版指纹，代价是升级/回退必须按顺序。
11. 模型子进程可自动恢复，但不自动覆盖遗留 Unix socket；代价是 runtime 崩溃后的 socket 清理需人工确认归属。

无单列延期的轻微审查问题；以上能力限制与真实验收缺口仍保留，不以全量测试通过掩盖。
