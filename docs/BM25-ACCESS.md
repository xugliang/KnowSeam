# BM25 与员工权限

## 检索

正文与查询使用同一份 Jieba 词典。正文分块保留完整原文、词频 TF（每个词出现次数）、分块长度和向量。
`sk_chunk_terms` 是 PostgreSQL 倒排表，`sk_chunks.token_count` 是分块长度；不是只存一组去重关键词。

关键词通道改用标准 BM25：`ln(1+(N-df+0.5)/(df+0.5))*tf*2.2/(tf+1.2*(0.25+0.75*dl/avgdl))`，
逐个不同查询词累加。k1=1.2、b=0.75。统计量仅针对本次授权范围内、当前有效版本、相同向量流水线的分块。
SQL 先授权再打分和截断；向量召回也先授权。两个通道各取候选、RRF 融合截断、Reranker 重排后再次核验权限。
旧 `tokens` / GIN 索引暂保留用于无损回滚，新检索不再使用 `ts_rank_cd`。

这是 PostgreSQL 原生 SQL + 倒排表实现，不是 pg_search 扩展。无需更换数据库镜像或增加搜索服务。
授权语料的 N 和平均长度按请求统计；适合当前规模，不能声称已验证百万级低延迟。
扩大规模前应做实际语料/并发基准，必要时引入独立 BM25 引擎或分区统计缓存（必须同时隔离权限）。

## 三层授权配置

```json
{
  "collections": [
    {"id": "public", "title": "全员资料", "visibility": "company"},
    {"id": "sales", "title": "销售部门", "visibility": "department", "departments": ["sales"]},
    {"id": "selected", "title": "指定员工", "visibility": "employee", "employees": ["employee-a"]}
  ],
  "employees": [
    {"actor_id": "employee-a", "active": true, "departments": ["sales"]},
    {"actor_id": "employee-left", "active": false, "departments": []}
  ]
}
```

这是完整配置的一部分；还需将资料来源绑定到集合，并给相应服务客户端配置 `allowed_collections`。
权限 = 服务凭据授权集合 ∩ 公司 ∩ 员工集合权限 ∩ 来源当前有效发布权限。
部门/员工集合的授权名单为空时，无人可读。未维护部门关系的已认证员工仍可读全员资料，不能读部门资料。
`actor_id` 是后端已认证的稳定员工标识，不是姓名；SuiteHarness 插件从请求 scope 获取，不能由 LLM 参数传入。
部门名单在服务端配置中维护，不接受调用者自报部门。指定员工集合可直接授权经过认证的该 ID。
显式停用员工一律拒绝；曾在 `employees` 配置中登记但后续删除的员工也被停用，避免移除名单时重新获得公共访问权。
管理者身份本身不提供读取全部资料的特权。部门与指定员工资料目前按**集合**划分，不是同一文档内部字段脱敏。

数据库保存 `sk_employees`、`sk_employee_departments`、`sk_collection_grants`，查询统一使用 SQL 授权谓词。
这不是 PostgreSQL RLS；数据库账号只供可信服务使用，不应分发给员工或模型。
列出集合、关键词/向量召回、直接读文档、重排序后的返回均受限。

飞书来源当前仍要求资料通过既有发布范围核验；集合权限可以收窄，不会把机器人能读取的任意私有文件自动开放。
任意飞书私有文档 ACL 自动同步不是本次实现，接入前需单独设计来源权限映射。

## 升级与名单变更

1. 备份数据库、配置和原镜像；停止旧同步 worker，避免旧程序写入无 BM25 索引的分块。
2. 用新代码运行 `init-db`：只做增量建表/列和配置授权同步，不删除旧数据。
3. 用相同词典运行 `migrate-bm25`：只为活动版本的未迁移分块补建词频表，不调用向量/重排模型；可中断重跑。
4. 启动新 API 与 worker；健康检查必须通过。未补建完的活动索引会让就绪检查失败，不默默降级。
5. 配置名单更新后，先停止 API/worker，运行 `init-db` 同步，再同时使用同一份新配置启动，避免旧配置覆盖新授权。

不要让多套不同配置的 worker/API 管理同一个公司的权限表。迁移前应核对来源 hash 和模型缓存标识，防止非本次改动引发全文重建。
回滚使用原镜像与原配置，保留新表和新列即可，无需破坏性删除。旧版本不支持新权限层级：
**启用受限集合后不得回滚到不检查权限的旧服务**，除非先撤销这些集合的来源和客户端授权。
